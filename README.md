# 周末大冒险 · 城市探索指南 ✦ CITY EXPLORER

> 一个为大学生打造的周末活动推荐 H5：1 分钟填偏好，拿到 3 个「有理由」的周末方案。
> 从 PRD 设计到部署上线全程由 AI Coding 协作完成，**3 小时内独立交付**。

## 🎯 解决什么问题

大学生周末决策成本高：去哪玩、几个人去、天气/预算影响大，朋友圈/小红书信息分散且不可量化。
**周五晚上花 1 分钟填偏好 → 拿到 3 个有理由的活动推荐 → 现场打卡 → 一键生成攻略分享卡。**

## ✨ 核心功能

| 模块 | 说明 |
| --- | --- |
| ① 开局设定 | 星座 / 心情 / 预算 / 同行人数 / 天气，5 维偏好输入 |
| ② 我的推荐 | 可解释推荐引擎，Top 3 方案 + 每条推荐理由 |
| ③ 抽卡转运 | 塔罗翻牌玩法，击中「选择困难症」场景，提升点击与分享 |
| ④ 打卡足迹 | localStorage 本地沉淀个人探索记录 |
| ⑤ 项目文档 | 完整 PRD、需求取舍、Prompt 草稿与迭代修复记录内嵌产品 |

## 🧮 可解释推荐引擎

推荐不是黑盒，每张卡片都列出实际命中的权重项，让用户知道「为什么是这三个」：

| 维度 | 权重 |
| --- | --- |
| 偏好匹配（活动类型 = 选中偏好） | +35 |
| 预算内（活动价格 ≤ 当前预算） | +25 |
| 天气适配（雨天室内 / 晴天户外） | +20 |
| 幸运方位（活动方位 = 今日幸运方位） | +15 |
| 人数适配（活动人数标记与同行人数匹配） | +10 |
| 幸运色加成 | +5 |

## 🤖 AI Coding 协作方法（vibe coding）

本项目的核心不只是产品本身，更是一套「人机协作交付」的实践：

- **分工**：作者负责产品方案 + Prompt 设计 + 验收标准；AI 工具负责代码生成与调试
- **四步法**：目标 → 拆解 → Prompt → 验收（源自实习期间智能体落地的实践沉淀）
- **任务拆解**：数据层 → UI 层 → 推荐引擎 → 玩法 → 装饰，先拆细再交给 AI 一次性生成
- **8 版迭代与回滚纪律**：每一轮都有测试验收（不是"应该能用"而是"测过能用"）；v7 因 UI 大改动导致体验倒退，果断回退 v6 备份——**只改用户点名的部分**

## 🛠 技术栈

- 纯前端单页应用：HTML / CSS / JavaScript，零依赖、无后端
- 数据存储：localStorage（打卡 / 组队 / 分享历史）
- 视觉：像素游戏风（致敬星露谷物语）+ 赛博朋克霓虹点缀，Canvas 星空粒子 + CSS 像素萌宠动画

## 📌 MVP 取舍说明

为什么不做实时群聊/讨论区/投票？——这是 MVP，目标是验证「用户能不能用 1 分钟做出周末决策」。实时通信会让后端复杂度过高、不利于单人独立交付，因此降级为「发起+报名」模拟。

## 🗓 后续规划

- 接入真实天气 API（高德/和风）
- 推荐解释升级为「不推荐项」——告诉用户为什么不选某个活动
- 组队接入实时通信（WebSocket / 轻量 IM）
- 活动数据接入大众点评/小红书真实数据流
- A/B 实验框架：验证「抽卡」vs「列表」的转化率差异
